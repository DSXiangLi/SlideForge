# 需求脑暴（Briefing v2）：维度池 + 实例化规则

> 对应 SKILL.md Step 0.5。原则：脑暴是**对齐不是问卷**——目的是在写第一行代码前冻结决策（第一性原则 1 的前移）。每组问题给默认缺省，用户没答就走缺省不追问；全部问题至多两轮交互。
> v2 升级（docs/design/brief-dynamic-brainstorming.md）：从"八组固定问卷"升级为"**维度池 + 实例化规则**"——维度骨架固定，问题文案与选项内容由 agent 结合主题/素材现场生成，经 `open_editor(brief_options=...)` 注入脑暴页渲染。**编辑器脑暴页是本文档的动态注入 UI 形态**（无注入时回落内建静态问卷，即下方维度池的缺省实例）；嵌入态由宿主经 `pptx-html:brief-options` 注入同一 schema。
> 设计文档 §6 是 `brief.options` schema 的单一真相；本文是生成纪律的单一真相。

## 维度池（八维度骨架，固定）

八个维度定义"问什么"；缺省值体系与派生规则（场景→密度/动效映射）不变。下列选项文案是**缺省实例**（静态回落/非 Bridge 降级时使用），Bridge 态由 agent 按实例化规则现场重写。

**① 使用场景**（单选）——决定密度与动效的默认锚点：
- 现场演讲（keynote）→ 缺省：低密度 + 标准动效 + 明暗节奏强
- 阅读分发（报告/文档）→ 缺省：高密度 + 克制动效
- 汇报答辩（限时讲完）→ 缺省：低密度 + 标准动效 + 页数经济
- 大屏/展台循环 → 缺省：低密度 + 华丽动效 + 高对比
- 网页嵌入/分享链接 → 缺省：高密度 + 标准动效

**② 受众**（单选）：技术同行（缺省） / 管理层 / 大众科普 / 客户或甲方——影响语言深度与「呈现发散」的隐喻选型（管理层偏结论先行 + 数据英雄页；技术受众可上架构堆栈与终端系主题）。

**③ 内容来源与切分**（单选 + 追问）：
- 从 0 到 1（主题/资料）→ 追问：叙事弧偏好——问题-方案-证据 / 时间线演进 / 总-分-总 / 对比论证（缺省：从内容里长出来，不套模板）；
- 现成 pptx 转换 → 走 SKILL.md Step 0 转换通道（内容重组非逐页复刻）；
- 已有大纲/文稿 → 直接进页计划表。

**④ 页数/时长预算**（单选）：≤8 页 / 8–15 页（缺省） / 15–25 页 / 不限——与密度档联动校验：高密度 + ≤8 页且内容多 → 提示加页或升密度。

**⑤ 视觉风格**（主题卡单选 + 变体）——来自 themes/index.md 的 20+ 重主题 × 变体；问法不是"选哪个主题"而是"这份内容应该是什么气质"，给 2–3 个推荐 + 全库自选。**品牌色适配纪律**：用户报品牌 VI 色时，不自定义 hex（禁忌不变）——选色距最近的变体并在简报中声明映射（"品牌红 #X → e8 号外红变体"）。
- **风格合理性回谏**：若用户指定风格与内容/场景明显不匹配（如合规报告选 Memphis 糖果风），agent 必须提出异议并给替代建议——回谏一次，用户坚持则从之并记录在简报。v2 起回谏**前移到 options 生成时执行**：`theme_pick.recommended` 即回谏结果，`reason` 写明依据。

**⑥ 字体偏好**（单选）：系统栈默认（离线，缺省）/ 接受联网字体（解锁主题 G2「display 联网备选」）/ 指定气质（衬线人文 / 黑体现代 / 手写温度——映射到主题 L2 层差异）。

**⑦ 动效与明暗**（各单选）：动效 克制/标准/华丽（五层矩阵语义不变）；明暗 亮底/暗底/混合节奏（缺省按主题世界决定）。

**⑧ 封面与交付**（多选 + 补充）：封面元素——主标题/副题/日期/演讲人/品牌位/章节目录（高密度档目录默认必载）；插画模式三态——`纯 HTML`（缺省）/ `AI 插画`（Step 5.5 管线，页内槽位生图）/ `混合烙入`（Step 5.6，选定页整页生图、文字烧死在图里）；选 `混合烙入` 时条件追问一句："哪些页适合做整页视觉？"——缺省驱动：不答则按"封面+各章节扉页+收束页"；尺寸——当前交付形态固定 16:9 网页版（声明项，不是选项）。

**自由补充**：任何不在上面的要求（口头禅、禁忌、参考物）。

## 实例化规则（agent 生成 brief.options 的纪律）

1. **选项现场生成**：每个进入 `ask` 的维度，由 agent 结合主题/素材/受众现场写 2–4 个选项（schema 上限 6），文案贴合本次任务（如受众维度不写"技术同行/管理层"枚举，而写"投委会成员""一线运营"这种从素材长出来的粒度）。
2. **必含两个锚**：一个推荐项（`recommended:true` + 一句话 `reason`，reason 是质量审计点，必须援引素材事实）和一个缺省锚（`default:true`，回落到维度池原缺省语义）。
3. **禁止兜底凑数项**（"其他""随便"之类占位选项）；**禁止向用户暴露推理过程**——reason 只写结论依据一句话，不写思维链。
4. **风格回谏前移**：主题推荐即回谏结果；品牌 VI 色不自定义 hex、映射最近变体的纪律不变（写进 `theme_pick.reason` 或 x-brand 条件组）。
5. **缺口驱动**：能从对话/素材推断的维度一律 `prefilled`（附 `prefill_reason` 推断依据），页面显示推断值可改而非重问；对话未涉及且缺省质量高的维度 `skipped`，收进页尾「未提及的维度」折叠区做缺省披露。
6. **上下文不足时先在聊天补问**（只问无法推断的），信息够了再生成 options 打开编辑器——不在页面里补救。

## 优先级与缺口表（替代"一律全问"）

| 优先级 | 维度 | 处置 |
|---|---|---|
| P0 | 主题与核心目标 | 来自对话，**不问** |
| P1 | 场景、受众、来源 | 对话/素材可推断 → `prefilled`；否则生成选项 `ask` |
| P2 | 风格、字体、动效明暗 | 风格走 `theme_pick`「推荐 2–3 + 全库自选」（策展元数据筛选机制）；字体/动效可 `prefilled` |
| P3 | 封面元素、插画三态、页数预算 | 缺省质量高，一律可 `prefilled` |

**素材驱动条件组**（id 白名单 `x-data` / `x-brand` / `x-fidelity`，由 agent 判定触发后写进 options）：

- 素材含大量数据/表格 → 追加 `x-data`「数据呈现偏好」组（图表密度、数据英雄页取舍）；
- 素材含品牌 VI（色号/Logo 规范）→ 追加 `x-brand` 品牌色映射声明确认组（映射最近变体，不自定义 hex）；
- 来源 = pptx 转换 → 追加 `x-fidelity`「保真度」组（内容重组 vs 逐页还原的取舍）。

## `brief.options` JSON schema 摘要（与 §6 一致）

```jsonc
{
  "version": 2, "kind": "brief-options",
  "context_summary": "agent 对输入的一句话消化（≤500 字，页面画像卡展示）",
  "profile": { "signals": ["data-heavy", "brand-color"] },   // 素材画像胶囊，≤12 项
  "groups": [ {
    "id": "scene",            // 固定枚举：scene/audience/source/pages/style/font/motion/cover + x-data/x-brand/x-fidelity
    "title": "使用场景", "impact": "决定密度与动效锚点",
    "state": "ask",           // ask | prefilled | skipped（prefilled/skipped 必填 prefill_reason）
    "prefill_reason": "素材明确写给管理层",
    "multi": false,
    "options": [ { "id": "report", "label": "汇报答辩", "desc": "≤120 字",
                   "recommended": true, "reason": "≤120 字依据" },
                 { "id": "read", "label": "阅读分发", "desc": "…", "default": true } ]
  } ],                        // 每组 ≤6 选项；ask 组 2–6 项；label ≤30 字
  "theme_pick": { "recommended": ["e3/red", "c3"],   // 1–3 个 主题/变体 id
                  "reason": "≤200 字", "library_open": true },
  "static_fallback": false    // true 时编辑器按静态问卷渲染（保留画像卡）
}
```

daemon 在 `open_editor` 携带该参数时做严格 schema 校验（枚举/字数/reason 必填等），非法拒收且会话保持原值；编辑器页面侧做轻量校验（kind/version/groups 结构），非法回落静态问卷。

**三态语义**：

- `ask`：常规卡片组，推荐项 ★ + reason，缺省项「缺省」小标；每组附「由 AI 决定」快捷项（采用 recommended，无则用 default），顶栏「全部按推荐」一键采用——提交时这些项按缺省语义标注；
- `prefilled`：折叠态一行「组名：推断值（依据）· 修改」，展开可改；未修改 = 接受推断值，**不标缺省**；
- `skipped`：页尾「未提及的维度」折叠区，展开可见缺省值说明（缺省披露透明），按缺省进简报。

## 简报输出格式（agent 与编辑器共用，v2 不变）

```
需求简报 · <一句话主题>
场景：<①> ｜ 受众：<②> ｜ 页数预算：<④>
内容来源：<③ 含叙事弧>
密度：<低密度/高密度> ｜ 动效：<档> ｜ 明暗：<…>
主题：<id + 变体>（品牌色映射：<如有>）
字体：<⑥> ｜ 插画：<⑧ 三态>
烙入：<页清单（混合烙入时必填，缺省=封面+各章节扉页+收束页）；纯 HTML / AI 插画时省略本行>
封面元素：<⑧ 多选>
自由补充：<如有>
风格回谏记录：<如有>
```

**结构化 JSON 的 `bake_intent` 字段**（编辑器脑暴浮板与 agent 手写简报共用口径，Bridge 模式 `brief.submitted` 冻结时随 json 携带）：仅当插画模式 = 混合烙入时出现——`bake_intent: { pages: string[], defaulted: bool }`。`pages` 是页清单数组：用户明确作答时为用户所填页（描述或预定 slide id），未作答时**缺省展开为语义清单 `["封面","各章节扉页","收束页"]` 并标 `defaulted: true`**（脑暴时 deck 尚不存在、没有真实页 id，所以缺省落为语义清单而不是 "auto" 标记——agent 在 Step 1 页计划表阶段把它落到具体 slide id，落点后即冻结，Step 5.6 不再逐页询问）。

**结构化 JSON 的 `extras` 字段**（v2 新增、可选）：x-* 素材驱动条件组的选择——`answers.extras: { "x-data": { choice, label, defaulted, prefill_reason? }, ... }`（仅 ask/prefilled 组进入；skipped 组按缺省处理不进入）。既有键结构不变，下游 Step 1/2 零感知。

## 纪律

- 缺省驱动：每组都有缺省，用户答几组算几组，缺省项在简报里标注（缺省）；
- 追问上限两轮：第一轮呈现问题组（编辑器脑暴页 = 一轮收敛），第二轮只追问矛盾项（如"阅读分发 + 华丽动效"需确认）；
- 脑暴结果冻结后进入 Step 1 页计划表——页计划表的密度/主题/动效档必须与简报一致，不一致处要在页计划表里说明谁改了谁。
