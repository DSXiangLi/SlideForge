## 一、G1 Schema 扩展（可选字段组，向后兼容）

单色主题零改动。多色主题在 G1 css 块内可追加三类 token（同步进校验器白名单，变体同样允许覆盖）：

| token | 语义 | 纪律 |
|---|---|---|
| `--accent-2` / `--accent-3`（+ 各自 `-on`） | 语义锚点扩展（如 kicker 一色/标题一色） | 每个必带 `-on` 配对（on-color 预配对，AA 纪律）；锚点总数 ≤3 |
| `--palette-1…N`（+ 各自 `-on`） | 类目轮转色序列——彩带/碎形/类目容器 | **固定顺序即契约**（index→colour，禁随机）；3 ≤ N ≤ 6；每色带 `-on` |
| `--hl-1…N`（+ 各自 `-hl-N-on`） | 荧光笔标注色 | 只以标注形态存在（高亮带/下划/描边），禁做容器面 |

图表开口：themes/index.md 图表 token 节增补——多色主题可显式声明 `--chart-series-1..8` 覆盖 color-mix 推导（声明即全序显式，禁止只覆盖部分档位）；单色主题维持推导不变。

校验器新增（sync-themes.mjs）：
1. G1/变体 css 允许多色 token 白名单（`--accent-N`/`-on`、`--palette-N`/`-on`、`--hl-N`/`-on`、`--chart-series-N`）；
2. 每个 `--palette-N`/`--hl-N`/`--accent-2/3` 必须有对应 `-on` 且均为合法 hex；
3. `--palette-*` 编号连续（1..N 不断档）；声明 palette 的主题必须在 G1 有「多色立场」字段（封闭色板禁令 + 分配规则 + 注意力色预算）。

防花纪律进 components.md §12 硬规则 7（多色容器）：彩色容器/彩带只许引用主题 palette 且按声明顺序轮转；彩色阴影的色相规则由主题 G4 显式声明（参考 peoples-platform 隐形红 vs daisy 墨色骨架两种相反立场都合法，但必须写明）；多色并列时结构线/正文字的墨色不变。

## 二、旧主题升级（名实不符兑现，方法论同 C3/E5）

| 主题 | 名实落差 | 升级内容 |
|---|---|---|
| **E4 包豪斯** | 三原色是包豪斯本质，现为单色红 | 加 `--accent-2` 黄 `--accent-3` 蓝；G9 基本形三件套定色分工（圆=红/三角=黄/方=蓝）；G1 立场：三原色平权、黑墨骨架 |
| **E1 孔版印刷** | riso 本质是多色套印，现单色粉 | 加 `--accent-2` 蓝；套色错位块双色叠印（multiply 已有机制，第二色进场）；G1 立场：双色版 = 双版印刷，错位即工艺 |
| **E6 孟菲斯** | 糖果世界多彩，现单色粉 | 加 `--palette-1..4`（粉/黄/蓝/绿糖果序）；碎形撒布按 palette 轮转；G1 立场：糖果罐封闭四色 |
| **C2 暗夜植物园** | accent 暖金，植物园无绿 | 补变体「苔径」：accent 转绿系（轻量修复，不动基底） |

升级红线：不破坏既有变体与 G1 六色；分化声明若引用被改主题的层签名需复核（E1/E4/E6 加 token 属 L1 分化增强，方向安全）。
