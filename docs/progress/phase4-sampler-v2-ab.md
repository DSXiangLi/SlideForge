## 2. 重做范围（用户选择：4 套升级主题）

当前只有 **B1 / C3 / E5 / H1** 四套主题写入了 G10 `composition_program`，
且全部经过角色化字号改造；其余主题没有「升级后版本」，重渲只是复刻旧图，不具 A/B 意义。

新 sampler 的技术口径：
- 内容对象：`tests/decks/theme-sampler/` 原页逐字。
- 字号：**只用** 骨架 v7.6 的 `.t-*` 角色类（逐字复用 `max(var(--t-*), floor)` 定义），
  不裸写 `font-size`；主题通过 `:root` 覆盖 `--t-*` 令牌（数值与各自 theme.md G9 css 块一致）。

- 构图：**按各自 G10 `signature_operator` 重新编译 DOM**，不是逐页换 token。
- 渲染：Playwright 驱动系统 Chrome，逐 `section` 截图 1920×1080；静态页面无入场动效，

## 3. 渲染与版面审计

脚本 `build.js` → `sampler.html` → `run.js` → 4 张 PNG + `report.json`。
`run.js` 检测四类问题：画布越界、容器内溢出、弱读（字号 ≥18px 且 opacity <0.9）、
同层文本块重叠（旋转元素因 AABB 虚胖已排除，避免误报）。

**rev3 最终结果（全绿）**：

| 页 | 文本节点 | 字号范围 | 层级比 | 画布越界 | 容器溢出 | 弱读 | 重叠 |
|---|---|---|---|---|---|---|---|
| B1 | 19 | 15–176px | 11.73:1 | 0 | 0 | 0 | 0 |
| C3 | 21 | 15–104px | 6.93:1 | 0 | 0 | 0 | 0 |
| E5 | 17 | 15–128px | 8.53:1 | 0 | 0 | 0 | 0 |
| H1 | 24 | 15–118px | 7.87:1 | 0 | 0 | 0 | 0 |

`pageErrors: 0`。

**迭代中修掉的问题**（这些是判断"视觉效果更好"的前提，否则对比不可信）：

| 轮次 | 问题 | 修复 |
|---|---|---|
| rev1 | B1 正文 `opacity:.82` 灰化弱读；C3 标题磷光辉光烧死字形（G9 明令禁止）、第 3 个 KPI 溢出窗口；E5 楔形块盖住 p1、p2 被力带压住；H1 汉数题跋被拆行 | 去灰化、去标题辉光、窗口增高、按力带旋转几何重排文字区并挪走楔形遮挡、题跋分行 |
| rev2 | 审计新增容器内溢出/重叠/弱读检测，抓到 C3「361家」仍溢出、E5 旋转标题 AABB 与正文重叠、H1 第一列超高、2 处弱读 | 重排 C3 窗口高度（290/226 → 532/262）、E5 按 `rotate(-12deg)` 实际几何把文字移到力带外、H1 列高 660→720、去掉 2 处淡字 opacity |
| rev3 | — | 全绿，目视复核 4 张确认无遮挡、无溢出、字形清晰 |

**为何 rev1 的溢出没被测出**：第一版审计只比对文本 bbox 与 1920×1080 画布，
C3 的 KPI 是"在画布内、但越出自己的描边窗口"，属于容器内溢出。rev2 起补上
「最近的、有显式 `top` + `height` 的绝对定位祖先」检测，才抓到这类问题。

## 4. A/B 对比结论

对照页：`compare.html`（4 组左右并排，8 张图全部加载成功），总览截图 `compare.png`。

### 4.1 核心发现：旧 Gallery 图文不符

抽查 Gallery 现役的 `p02-b1` / `p05-c3` / `p14-e5` / `p16-e7` / `p25-g1` / `p22-f1`，
**12 张全部共享同一版式骨架**：大标题 → 两段正文 → **横向等权三格 KPI** → 三条列表 → 脚注，
元素位置几乎逐像素一致，差异仅来自配色、字体与背景装饰。

而 README 第 89 行写的是：
> themes differ systematically in **layout**, texture, and graphic language, **not just color**

旧图实际只做到 "color + texture"，**layout 没变**。且「横向等权三格 KPI」正是 B1
G10 契约 `forbidden_defaults: [三格等权 KPI, 居中 hero, …]` 明令禁止的默认构图。
旧 E5 尤其典型：红斜带只是贴在标题后面当背景，黑字压在红带上，KPI 仍是横排三格 ——
力带没有成为"决定信息如何进入空间的程序"。

### 4.2 新版的实质提升

| 维度 | 旧 sampler | 新版 sampler |
|---|---|---|
| 信息结构 | 4 主题同骨架，只换皮 | 4 主题各自重编译：12 栏网格＋数据脊 / stdout 时间流 / −12° 力带＋楔形 / 竖排题跋分列 |
| 主题识别度 | 遮住色相后几乎无法分辨 | 遮色缩略仍可分辨（网格 / 终端窗 / 斜带 / 竖排） |
| 字号层级 | 正文 19px、数字 60px，比 ≈3:1，且正文多次 opacity 灰化 | 角色类驱动，层级比 6.93–11.73:1，正文不降透明度 |
| 契约一致性 | 旧 E5 保留「三格等权 KPI」= 违约 | KPI 分别改为纵向数据脊 / key:value 行 / 沿力线阶梯 / 汉数题跋 |
| 可读性 | 正文偏小偏灰 | `max()` 下限锁死，实测零弱读、零溢出、零重叠 |

### 4.3 是否可替换（结论：**建议替换，但本轮未执行**）

| 优先级 | 目标席位 | 建议 | 理由 |
|---|---|---|---|
| 高 | Gallery 中 `p05-c3`（C3 终端绿） | 用 `new-c3.png` 直接替换 | 同主题同内容，新版命令行＋描边窗口＋key:value 是旧版「绿底＋横排三格」的严格升级；旧版标题还有烧死字形风险 |
| 高 | Gallery 中 `p16-e7`（E7 浮世绘）或任一"东方/文化"席位 | 用 `new-h1.png` 增补 | H1 是旧 sampler 完全没有的新主题，竖排＋题跋＋朱印的构图辨识度显著高于 E7（E7 只是同一骨架＋底部波纹＋角落红印） |
| 中 | `p14-e5`（E5 构成主义）当前不在展示 12 张内 | 若扩展示位，`new-e5.png` 优先 | 旧 E5 的力带只是背景、标题压带，新版力带真正承载标题并组织对抗关系 |
| 中 | `p02-b1`（B1 瑞士）当前不在展示 12 张内 | 可作 "12 栏网格" 代表补位 | 数据脊与单点 accent 面积事件最直观地体现「同一内容如何被构图程序改变」 |
| 低 | 其余 8 张 Gallery 现役主题 | 暂不动 | 未做升级版，无同内容 A/B 依据；且用户已选「先不替换」 |

**不建议整体替换 Gallery 12 张**：新版只覆盖 4 套主题，直接替换会让 Gallery
的 "One Deck × 12 Themes" 标题与实际内容不符，也会丢失 F/G 系列（光学轴、多色）的展示。
更稳妥的路径是保留 12 张骨架、先换 1–2 张最弱席位做试点，或另起一小节展示
「主题 DNA：同一内容 × 构图程序」——但那需要你另行确认，本轮不擅自改 Gallery。

### 4.4 一处诚实的边界

新版 4 页是**单页高密度内容页**（1.1 整体特色及优势），不是完整 deck；
旧 Gallery 也是单页，因此 A/B 是公平的。但 G10 契约的完整威力体现在
6 种页面类型（封面/目录/主张/分析/图表/收尾）的整 deck 一致性上 ——
这部分在 `analysis/dna-pilot.html`（24 页）里验证过，但那份用的是自造内容，
不能与本次「一杯好茶」内容混为一谈。若要下"整 deck 替换"的结论，
需要再补一轮「同一份山禾集内容 × 6 页型 × 4 主题」的渲染。
