## 2. 事实纠正：脑暴**不是**独立工具

用户提问时以为"脑暴页面已单独作为 tool 拎出来"。实际仍是**一个工具四视图**：`open_editor` 承载
brief/edit/annotate/export，靠 `_meta.ui.mode = "pip"` + `mode_inline_when = {arg:"view", in:["brief"]}`
条件化形态（`tools/bridge_mcp.py:208-213` 有明确注释：形态是工具级静态声明、表达不了按视图区分）。

同时工作台上**本来就没有脑暴入口**——`openBrief()` 全仓唯一调用点是首屏分流 `launchEnterBrief()`，
没有任何按钮绑它。真正存在的是**反方向**的问题（进了脑暴只能靠 `✕` 出来，想再回去只能让 AI 重新
`open_editor(view="brief")`）；经确认**不加回入口**（脑暴只在开工前一次性采集需求）。

**设计原则（写给后续同类改动）**

1. **说用户的话**：按钮说"用户能得到什么"，不说"系统做了什么"（"整页重绘" > "重烙"）。
2. **后果可见**：异步、要花钱、可能失败的动作（重绘/补图/导出）在 `title` 里讲清会发生什么、要不要等、可能失败。
3. **两类动作分开**：`请 AI 干活`（重绘/补图/导出）与 `你自己改`（改字/换图/保存）在提示语上必须能区分——前者一律带"提交后进入 AI 队列，完成后自动刷新"这类说明。
