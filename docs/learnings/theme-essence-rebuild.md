# 主题本质重建经验教训

> 来源：1012–1013 主题本质优化全流程（E1/E4/E5/G1/G2/G4/G5 七主题 + E6 四轮迭代），记录视觉原理层面的发现。

## 一、结构替换 ≠ 骨架重建

第一批改动只做了"删 masthead、换 .reveal → data-anim、调 padding"——前后截图几乎无差异。原因：这些是表层属性替换，页面的内容排布方式（居中内容带）、容器形态（白底加色块装饰）、视觉重量关系（字轻块重）全没动。

**正确做法**：逐页重写 HTML 结构——内容坐在什么上面、容器长什么样、文字和形的重量关系，全部从 unforgettable 推理出来。用子 agent 从零生成每页 HTML，而不是在旧 HTML 上做 sed 替换。

## 二、字重和色块的视觉博弈

几何形色块视觉重量极大，字体必须匹配甚至超过它：

- **大色面上的文字**：font-weight ≥600，不能用 200-300——细字在大色面上像水印
- **KPI 数值**：必须 700+，是页面最重视觉元素
- **层次阶梯**：数值(700) → 名称(500) → 标签(600 mono) → 说明(500)，不能全 300-600 扁平分布
- **字重倒挂的前提**：纯文字页成立，一旦引入色块就崩——色块的重量需要字重对冲

## 三、色块要避让文字，不是吞噬文字

色块尺寸要给文字留呼吸空间。大红方块 640×640px 填满半页，文字在里面像溺水。缩小到 480×480px 并调整文字位置后，色块变成构成元素而不是背景幕布。

**规则**：色面容器的内边距 ≥32px；单页最大实色面 ≤画幅 1/3；文字在色面上的占比 ≤色面 60%。

## 四、旋转不足以立主题

E1 只靠 ±1.5° 旋转 = "歪了的方框"，不是"贴上去的纸片"。拼贴卡需要多重纸感线索叠加：

- **纸面变化**：不是全部 paper-tint，要 paper / paper-tint / 混合色 三种轮转
- **边缘纸感**：2px 主边框 + 1px outline + offset = 双层纸边，模拟裁切边缘
- **手工痕迹**：戳记、半调点纹理、裁剪虚线装饰——这些"不完美"才是 zine 的灵魂
- **层叠感**：卡片之间要有 z-index 错位或 outline-offset 制造的层叠错位感

**规则**：一个视觉母题（旋转/材质/层叠）单独使用不足以立主题，至少需要 2-3 种线索叠加。

## 五、端到端优化清单

每次主题优化必须走完全流程，不能跳步：

1. **更新 theme.md**：从 unforgettable 推理出本质规范表 + 骨架硬规则
2. **子 agent 从零生成**：给子 agent 完整内容数据 + 主题硬规则 + 结构指令，让它从零写 HTML
3. **替换进 deck**：用正确的注释标记做边界，确保旧内容完全替换
4. **溢出检查**：Playwright 逐页检测 data-editable 元素是否超出 1920×1080
5. **font-weight 审计**：确保不存在 200/300（除非主题明确要求细字且无色块）
6. **截图对比**：生成 before/after 截图，肉眼确认差异显著
7. **content-hash 更新**：extract-manifest.py --write-hashes
8. **对比页面**：生成 HTML 对比页供用户验收

## 六、两个主题各自的坑

- **包豪斯**：字重倒挂（200 细标题）在纯文字页成立，但一加色块就崩——色块的重量需要字重对冲
- **孔版印刷**：拼贴不等于旋转——拼贴是层叠、错位、纸材质差异的组合，旋转只是其中一个维度

## 七、视觉原理：并列信息与有主次信息的布局规则

> 来源：E6 孟菲斯 v2→v3→v4 迭代中发现的问题。

### 原理 1：并列信息等大对齐，有主次信息大小不等

**问题**：v2/v3 在目录章节（4 个并列的章节项）上使用大小不等的色面块"散布"在版面上——观众第一反应不是"01→02→03→04 的顺序"，而是"为什么有的块大有的块小？它们什么关系？"

**原理**：大小差异在没有对齐基准的情况下传递的是"重要性差异"信号。当信息实际上是并列的（4 个章节是平等的），大小差异制造了**虚假的层级关系**，增加认知负担而非信息引导。

**规则**：
- **并列信息**（目录章节、4 种店型、4 个流程步骤）→ **等大对齐**横排或 2×2，颜色轮转区分，全部统一投影（全有或全无）
- **有主次信息**（KPI 有焦点项、漏斗有断点）→ 焦点块**更大** + **8px 投影**，辅助块更小 + 无投影
- **大小不等只在信息权重确实不同时使用**——不是视觉花样，是信息编码

### 原理 2：投影一致性 = 信息一致性

**问题**：v3 在并列信息上使用不一致的投影（有的块 8px 投影有的没有），本意是"焦点块重、辅助块轻"，但在并列信息上传递了错误信号。

**原理**：硬偏移投影的视觉重量很大（8px 0 no-blur 的黑影），在并列信息上不一致使用相当于说"这个比那个重要"——当信息实际上平等时，这是误导。

**规则**：
- 并列信息 → 全部统一投影（全有 8px 或全无）
- 有主次信息 → 焦点块 8px 投影，辅助块无投影或 4px 投影
- 投影差异是信息权重的编码，不是视觉装饰

### 原理 3：高对比色面块必须占满可用宽度

**问题**：v3/v4 使用固定小尺寸色面块（360×170px）放在 1920×1080 画幅上，色面块只占画面的一小部分——显得"抠抠搜搜"。

**原理**：高对比度的色面块（3px ink 描边 + 糖果色填充 + 硬偏移投影）本身视觉重量极大。当它只占画面的一小部分时，视觉重量与画面空白产生失衡——像在大房间里放了几块积木。大色面在大画幅上才成立，小色面在大画幅上显得小气。

**实证**：frontend-slides 的 Creative Mode stat-cell 是满宽的（占满 12 列网格），Studio 的 stat-card 也是满宽的——数据色面块都是占满可用宽度的，不是漂浮在空白中的小方块。

**规则**：
- **色面块应占满可用宽度**（或接近全宽），不是漂浮的小方块
- **多块并列时横排占满全宽**——每块等分宽度，不是固定小尺寸+大间距
- **2×2 排列时每块占满半宽半高区域**
- **投影是色面块的延伸**——块越大投影越合理；块越小投影越突兀

### 原理 4：倾斜容器破坏信息可读性

**问题**：E1 v1 使用 ±1.5° 旋转的拼贴卡，E6 v1 使用旋转的便签卡——用户反馈"字歪七扭八无法传递信息"。

**原理**：PPT 的核心功能是传递信息。文字倾斜后阅读速度下降、认知负荷增加——在需要快速读取数据的场景（KPI、详情表、图表标注）尤为严重。倾斜在纯装饰元素上可以接受，在承载信息的容器上不可接受。

**规则**：
- **信息容器不可倾斜/旋转**——文字必须正放可读
- 倾斜只用于纯装饰元素（彩纸屑、戳记标记等 `data-editable-skip` 的元素）
- 如果主题需要"手工感"或"拼贴感"，用其他方式实现：纸面变化、边缘质感、层叠错位，而不是倾斜

### 原理 5：布局传递信息，装置传递风格——两者叠加

**问题**：v2 把"不用 grid 均匀排列"理解成了"完全不要布局"，色面块散落在版面上没有任何视觉引导，观众不知道该先看什么。

**原理**：PPT 的核心是通过布局、字体、高亮、颜色完成观众的视觉引导。视觉装置（色面块、硬偏移投影、之字线等）是风格的载体，不是信息的替代。布局必须先建立阅读路径（从左到右、从上到下、从大到小），然后视觉装置增强这条路径的体验——而不是用装置替代路径。

**规则**：
- 每页必须有明确的阅读路径（用大小、位置、颜色权重建立）
- 视觉装置增强阅读路径，不替代它
- 装置的方向（之字线从左到右）、颜色（palette 轮转编码顺序）、重量（投影大小编码权重）都应服务阅读路径

### 原理 6：色面块尺寸由内容决定，不由视觉随意性决定

**问题**：v3 为了"大小不等"压缩部分色面块尺寸，导致文字溢出。

**原理**：色面块是信息的容器，尺寸必须先满足内容需求（文字行数、数据精度），再考虑视觉比例。为了视觉效果压缩内容空间是本末倒置。

**规则**：
- 先确定内容需要多少空间（文字行数 × 行高 + padding），再定色面块尺寸
- 并列信息的色面块按最大内容块的尺寸统一——不是按最小内容块压缩
- 宁可色面块大一些留白，也不能小到文字溢出

### 原理 7：同一布局换皮 ≠ 主题差异化

**问题**：所有主题的 8 种页型用完全相同的信息结构——cover=大标题+副标题+描述，high=4KPI卡片+详情表+年份卡，只是换了色和字。

**原理**：主题差异化的本质是**视觉元素组合方式的差异**，不是单一维度的色值替换。同一信息密度在不同主题中应该用完全不同的布局方式、容器形态、字体处理、装饰策略来呈现。frontend-slides 的三个模板对同一信息密度的处理方式有本质差异：Creative Mode 用色面块网格，Studio 用 2px 顶线极简字段，Mat 用 1px 竖线分隔字段行——三个模板都没有用"卡片网格"。

**规则**：
- 每个主题 × 每种页型都应从主题的视觉装置推理出该页型的具体布局方案
- 不用统一的页型模板换皮
- KPI 呈现、详情表、信息图、图表都应有主题独有的容器和布局方式

### 原理 8：主题灵魂 = 视觉装置，不是配色方案

**问题**：早期优化把主题理解为"配色方案 + 字体选择"，导致只换了色和字，骨架不变。

**原理**（来自 source/ 研究）：每个主题的灵魂是一个**可落到 CSS 属性的物理机制**（视觉装置），不是氛围描述或配色方案。Studio 的装置是"字重极端到字变成形状"，Mat 的装置是"径向辉光做唯一深度源"，Creative Mode 的装置是"4px 墨边+硬偏移投影做布局"。装置的物理前提强迫出骨架规则——Studio 因为字是主角所以禁第三色、禁阴影、禁圆角。

**规则**：
- 每个主题必须有一个可落到 CSS 属性的视觉装置（一句话：XXX 做 YYY）
- 装置的物理前提推理出骨架硬规则（不是"我想规定什么"，而是"装置的物理前提强迫什么"）
- 配色变体只换 hex 值，装置行为规则跨变体共享

### 原理 9：Framework JS null 引用会隐藏全部内容

**问题**：`document.getElementById('chrome')` 返回 null（deck 无 `id="chrome"` 元素），`chrome.textContent = ...` 抛出异常导致整个 framework JS 崩溃，IntersectionObserver 未初始化，所有 `data-anim` 元素永远停留在 `opacity:0`，页面完全不可见。但在 `reduced_motion='reduce'` 测试环境下 `.js` 类不被添加，`data-anim` 元素不受 `opacity:0` 影响，截图看起来正常——**测试通过但真实浏览器白屏**。

**原理**：framework JS 的 `data-anim` 机制是渐进增强——`.js` 类添加到 `<html>` 后，`[data-anim]` 元素初始为 `opacity:0`，只有 `.slide.in-view [data-anim]` 才变为可见。如果 JS 崩溃，`in-view` 永远不被添加，所有动效元素不可见。这种"测试环境通过但生产环境失败"的问题难以发现。

**规则**：
- Framework JS 中所有 DOM 引用必须做 null 检查（`if (el) el.textContent = ...`）
- 测试时不能只依赖 `reduced_motion='reduce'`——必须在非 reduced-motion 模式下也验证页面可见
- 每次修改 deck 后，在真实浏览器（非 reduced-motion）中打开验证页面可见

### 原理 10：参考图数据源必须一致

**问题**：更新主题 demo 图时，从 theme-proving deck 截图替换了 theme-sampler deck 的图——两个 deck 用不同内容（theme-proving 用"山禾集"经营报告，theme-sampler 用统一展示页），导致 README 中的主题样张与主题验收四宫格用了不同内容，视觉上不一致。

**原理**：参考图是主题的"门面"——不同展示场景（sampler / proving / README）应使用各自 deck 的正确数据源。sampler 图来自 sampler deck，proving 图来自 proving deck，不能混用。

**规则**：
- `assets/theme-sampler/` 图来自 `tests/decks/theme-sampler/`（每主题 1 页展示页）
- `assets/theme-proving/` 图来自 `tests/decks/theme-proving/`（每主题 8 页四宫格）
- `themes/*/demo-1.png` 来自 sampler deck，`demo-2.png` 来自 proving deck（high 页）
- README 主题样张用 sampler 图，主题验收四宫格用 proving 图，不混用
