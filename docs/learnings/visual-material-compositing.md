# 视觉材料与 CSS 合成技术经验教训

> 来源：2026-10-15 外部视觉风格参考项目深度对比分析（封面/海报/头图风格库 33+25 风格），抽象出 HTML 层可用的设计原理。

## 一、材料语言是视觉出挑的第一来源

外部参考的每个风格都精确描述物理材料及其光线条件——不是"纹理"这个抽象标签，而是"涂漆钢 + 磨损油墨""击凸棉纸 + 柔和侧光""细密平行排线 + 交叉排线 + 点描"这种物理级描述。

**当前差距**：L3 质感层只有 6 个抽象类型标签（flat/grain/glow/paper/hand-drawn/aura），80% 主题标为 `flat`。G9 母题块的 CSS 实现多数停留在"颜色+边框+阴影"——不是 CSS 能力不够（骨架框架有 conic-gradient、@property、offset-path、mask-composite、backdrop-filter 等全套基础设施），而是主题定义没有把"材料"写进去。

**原理**：主题的灵魂是一个可落到 CSS 属性的视觉装置（已有认知），装置必须回答三个问题——这个世界的表面材料是什么？光怎么打在它上面？哪个 CSS 合成技术可以模拟？

## 二、CSS 合成技术利用率不足 15%

CSS 提供了约 35 种图层合成/材质模拟技术，当前系统只用了约 5 种：

### 已使用（5 种）

| 技术 | 主题 | 效果 |
|---|---|---|
| `mix-blend-mode: multiply` | E1 孔版 | 套色错位叠印 |
| `backdrop-filter: blur()+saturate()` | F1 玻璃 | 毛玻璃 |
| `mask-image: linear-gradient` | F2 霓虹 | 倒影渐隐 |
| `filter: blur()` | F1 光斑 | 景深虚化 |
| SVG `feTurbulence` + `feColorMatrix` | E1 孔版 | 纸张颗粒 |

### 未使用但有明确材料映射（12 种关键配方）

| CSS 配方 | 模拟的物理材料 | 适用主题方向 |
|---|---|---|
| `mix-blend-mode: screen` | 光线叠加、霓虹辉光、投影光束 | F 系光主题、C1 信号黑 |
| `mix-blend-mode: overlay` | 纹理压印在颜色上、纸纹覆盖 | D 系、A1 杂志 |
| `mix-blend-mode: soft-light` | 柔和环境光、做旧褪色 | D2 暗房、复古主题 |
| `mix-blend-mode: color-dodge` | 极亮高光、灼烧感 | C1 聚光灯焦点 |
| `filter: drop-shadow()` | 沿 alpha 通道的物理投影（非矩形投影） | 不规则图形/异形元素 |
| `filter: sepia() contrast()` | 做旧、泛黄、褪色 | D2 暗房、复古主题 |
| `mask-image: radial-gradient` | 聚光灯光斑、暗角 | C1 信号黑 |
| `mask-image: url(SVG)` | 不规则遮罩（撕纸边缘、有机形状） | 拼贴/手绘主题 |
| `background-blend-mode` | 多背景层混合（比 mix-blend-mode 轻量） | 全主题通用 |
| SVG `feDisplacementMap` | 有机扭曲、手绘笔触 | 手绘/水彩主题 |
| SVG `feMorphology` | 墨迹扩散/腐蚀 | 印刷/印章主题 |
| SVG `feComponentTransfer` | 半调网点、色调分离 | 印刷主题 |

### 导出轨道约束

| 技术族 | 保真轨（PDF→SVG） | 可编辑轨 |
|---|---|---|
| mix-blend-mode | 保留（可能被栅格化——可接受） | **丢失** |
| filter 系 | 保留（栅格化） | **丢失** |
| mask-image | 保留（clipping path） | **丢失** |
| backdrop-filter | 待实测（Chromium print 管线可能不渲染） | **丢失** |
| SVG filter data-URI | 保留（作为图片渲染） | **丢失** |

**推论**：主题身份是双层的——**可编辑身份**（色+字+形，L1/L2/G4）穿透两条轨道，**保真身份**（材质+光+合成，L3/G9）只穿透保真轨。当前系统的问题不是缺少这个分层，而是保真身份层太薄。

## 三、标题处理必须按页面角色分级

外部参考的标题技法（巨型透视标题、图文穿插遮挡、标题被坐标重构）全部隐含"低密度单图"前提。PPTX 有 5 种页角色 × 2 种密度档，标题策略必须分级：

| 页角色 | 标题策略 | HTML 可实现手段 | 密度约束 |
|---|---|---|---|
| cover / divider | **标题即建筑**——透视/遮挡/材质化 | `transform: perspective()`、`z-index` 分层、`-webkit-text-stroke`、`background-clip:text` | 仅低密度 |
| key-message | **标题即主角**——巨字标准渲染 | `font-size: clamp()` 巨字、字重对比 | 低密度 |
| analysis | **标题即编辑排版**——正常字号 | 标准编辑排版 | 高密度 |
| analysis 背景层 | **Ghost 核心词**——低透明巨字背景 | A1 Ghost 字模式泛化：2–8 字核心词、8–15% 透明度 | 高密度合法 |

**关键发现**：外部参考中"咨询报告视觉"风格的 A/B/C 标题分层（A 层核心词巨字 + B 层完整标题正常 + C 层标签 mono 小字）天然适配高密度页。这不是把标题做大，而是把标题**拆成两个层级**——A 层承担视觉冲击，B 层承担语义完整。

## 四、观看序列 → 动效揭示顺序

外部参考定义了"远看剪影 → 近看排线 → 再近看点描"的空间观看序列。HTML 可以在**时间维度**上实现同等效果——动效揭示顺序对应信息层级：

- 环境层先出现（背景光晕/质感层 fade-in）
- 焦点元素第二位（标题/关键数字，主题签名入场）
- 内容层最后（正文/数据 rise-in/wipe-clip）

当前骨架的阶梯延迟（stagger delay）只是"依次出现"的技术机制，缺少"先看什么后看什么"的设计意图声明。

## 五、主题级反惰性规则

外部参考的每个风格有专属禁用项——"不要因为主题涉及 AI 就加机器人""不要把设计感理解为金属雕塑"。当前系统只有全局骨架红线（禁 masthead/reveal/hairline），缺少**主题级**的"这个主题最容易滑向什么惰性"。

每个主题应声明 2–3 条专属反惰性规则，格式为"不要因为___就___"。例如：
- B1 瑞士：不要把十字标当装饰花边撒满页面
- E6 孟菲斯：不要用超过 4 种配色
- F1 玻璃：不要让玻璃卡片漂在纯色背景上（必须有光斑底层）

## 六、边缘裁切作为合法张力手段

外部参考大量使用"主体占画面 40–80% 或被边缘大胆裁切"。当前系统所有元素都在安全区内，缺少"出血"语言。

**合法范围**：仅低密度仪式页（cover/divider/closing）。实现方式：`.slide` 已有 `overflow: hidden`，超尺寸装饰元素（accent 色块、母题件、背景图形）可以越界被裁切，制造"比页面更大"的视觉张力。文字内容不受此影响。

## 七、同一世界两种渲染——HTML 与 bake 的材料一致性

G9 母题 CSS 和 bake_brief 是两套独立定义，缺少"材料-光线"共同锚点。结果是 HTML 版和 bake 版可能看起来像两个不同的东西。

**原理**：G9 CSS 是该材料在 HTML 中的尽力模拟，bake_brief 是同一材料在生图中的精确表达。两者应共享一个 `material_world` 描述——用户看到的是同一个物质世界的两种渲染，HTML 版是"这个世界的线框图"，bake 版是"这个世界的高清照片"。
